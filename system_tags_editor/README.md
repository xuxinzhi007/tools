# system_tags.json 可视化编辑

改 system_tags.json 不用手改大 JSON：质检标签的 `device_scope`（任务类型 / 本体 / 设备型号）+ 全部标签树（质检 / 数采任务 / 标注任务 / 通用场景）的增删改。

## 用法

```bash
cd /Users/xuxinzhi/Documents/gowork/tools/system_tags_editor
go run .
# 或构建单二进制：go build -o tags-editor . && ./tags-editor
# 局域网访问：默认 0.0.0.0，启动时打印 LAN 地址
```

浏览器打开提示的地址（默认 http://127.0.0.1:8765）。

标签相关页面都从这里进：

- `/` 标签树编辑
- `/tools/pretrain-resync` 预训练三维标签重刷（核对表 + 刷入 SQL）
- `/tools/label-repair` 任务标签 L1 脏数据修复 SQL
- `/tools/qc-init` 质检标签 List 转 Init / 删除 SQL

## 预训练重刷

只看已绑 `pretrain_large_scale` 的任务。后三列是要刷进 `tb_job_tag` 的目标叶子，不是筛选条件。命中顺序从上到下，未命中不刷。

| 规则 | 筛选 | 是否移动 | 是否工厂 | 指令颗粒度 |
| --- | --- | --- | --- | --- |
| 1 外采概括 | 有本体，topic 后缀 `_free` | 移动 | 非工厂 | 概括描述 |
| 2 外采详细 | 有本体，topic 含 `_zhengjioutside` 且不含 `_free` | 移动 | 非工厂 | 详细指令 |
| 3 工厂整机/桌面 | 有本体，且不是 1、2 | 非移动 | 工厂 | 详细指令 |
| 4 无本体官方 | 无本体，`job_source=LLM`，创建日落在所选日期 | 非移动 | 非工厂 | 概括描述 |
| 5 无本体移动 | 无本体，场景名含（移动） | 移动 | 非工厂 | 概括描述 |
| 6 无本体工厂 | 无本体，场景名含工厂 | 非移动 | 工厂 | 概括描述 |

有本体 = 采集设备不在勾选的无本体型号里。场景取 `tb_job_tag.relation_type = SCENE`。每条规则单独生成查询和刷入，一次只跑一条。

- **从仓库加载 / 写回仓库**：读写  
  `../../data-service/configs/tag/system_tags.json`
- 也可本地选文件导入、导出下载（导出与写回共用 compact 格式）
- 标签与分类均可新增 / 删除 / 改名（等同直接编辑 JSON；未知字段写回时原样保留）
- 侧栏切换标签树；多层树（如数采任务）用「进入子标签」下钻；`device_scope` 编辑与批量操作仅质检树有
- **租户白名单 `tenant_tag`**（仅任务类标签：数采 / 标注 / 通用场景；质检标签不受影响，仍由 `device_scope` 控制）：
  - 留空 / 不写 = 仅主租户 888888 可见；勾选 = 对应租户（如 `BODYLESS` 无本体租户）可见
  - 卡片上直接勾选「无本体租户」等选项（与质检标签任务类型勾选同一交互），不勾 = 仅主租户
  - 背景：`common_tags.json` 准备淘汰，所有租户统一用 `system_tags.json`（参考 data-service `feature/v8.20_sys_qc_tag` 分支）
- 加载 / 导入时检测重复 code 并提示
- 写回前弹窗展示行级 diff，确认后才落盘

## 规则提示

- `job_types` **不勾 = 通用**（全任务类型）
- 勾选了 = **白名单**，仅这些类型可见
- 任务类型：1 自由 / 2 定制 / 4 生成 / 8 恢复 / 16 纯推理 / 32 接管 / 64 评测 / 128 强化学习
- 「专家摇操」为组合勾选（= 1|2|4，新平台对数采自由+定制+生成的统一叫法，后端无独立 bit）；1/2/4 齐时状态行也显示为专家摇操
