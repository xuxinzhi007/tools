任务标签脏数据修复 SQL 生成器

场景：租户内存在手动创建的 L1 分类（无 tag_code），与系统固定 L1（如 annotation_task_label）重复。 将旧 L1 下的子标签迁移到系统 L1。
当前后端 API 不支持修改 parent_id，请用本工具生成 SQL，在 Navicat / mysql 客户端执行。

执行前请先备份 tb_tag、tb_job_tag。Navicat / DBeaver 请每条 SQL 单独选中执行（不支持 SET @var 多语句批跑）。 若系统 L1 尚不存在，先跑 docs/SQL/seed_system_label_tags_<tenant>.sql。

参数

Global 系统固定标签填 0；租户内 lazy ensure 填具体租户如 888888。

例：tag-dc5umtfiwe4fgeks — tag_name=标注任务标签，tag_code 为空

点击上方按钮生成 SQL。

说明

  • 不等于 API 修复：Tag Update 接口不能改 parent_id，只能 SQL 或后续专用运维接口。
  • 修复后 ListTags / InternalListTags 按 parent_tag_code 查树，子标签会出现在系统 L1 的 sub_tags 下。
  • 若「迁移前诊断」出现同名冲突，需人工合并或改名后再执行 UPDATE。
  • 旧 L1 默认不禁用；可选「修复 + 禁用旧 L1」将 status=1，避免前端仍选到重复分类。
  • Navicat / DBeaver：每条 SQL 单独选中执行，不要用 SET @ + 多语句批跑。
  • 相关脚本：docs/SQL/repair_duplicate_label_l1.sql、seed_system_label_tags_888888.sql
